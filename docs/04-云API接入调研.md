## 已核实的硬参数

### Seedance 2.0 系列（官方文档）

```
参考视频   时长 [2, 15] s · 最多 3 个 · 总时长 ≤15 s
参考图片   1~9 张（全模态参考生视频）
分辨率     480p / 720p / 1080p / 4k
宽高比     [0.4, 2.5]
宽高 px    [300, 6000]
总像素     [407,696, 8,295,044]        ← 852×480 = 408,960 满足
单视频     ≤200 MB · 帧率 [24, 60] · mp4/mov
单图       <30 MB · 请求体 ≤64 MB · 不建议 Base64
音频       2.0 系列不可单独输入，需至少 1 视频或图
```

**与我们 `video_ref.py` 的 LIMITS 逐条吻合** —— 规格校验已就绪，缺的只是 Channel。

### Seedance 2.5

```
参考视频 [2,30] s · 最多 10 个 · 总 ≤30 s
参考图片 0~30 张 · 参考音频 0~10 个 · 可仅传音频
支持 30 秒连贯直出 · 支持视频编辑与延长
```

### Vidu（官方定价页）

```
1 credit = ¥0.03125
参考生视频 viduq4-preview 3~16s @4k = 78 credits/秒  ≈ ¥2.44/秒 → 5s ≈ ¥12.2
⚠️ 低分辨率档（480p/720p）单价未取到，必须查 —— 否则无法判断能不能跑 A/B
```

**关键判断**：Vidu 的"低至 4 分钱"指的是**最低档**；
我们白模是 852×480 → 应落在低档，**但具体单价必须查清**。

### 阿里云 万相 3.0（官方 API 参考）

```
media 数组：{ type, url }
  type = first_frame | reference_video | reference_image | reference_audio
数组顺序即 prompt 里的「视频1 / 图1 / 音频1」编号
```

## 接入成本（架构层面，四家一样）

因为 `alpha.130` 已把后端选择抽出来，接一家 = **四件事**：

```
1  Backend 条目（kind / endpoint / api_key_env）
2  Channel（提交 → 轮询 → 取产物）
3  LIMITS（复用 video_ref.violations()，超限本地就拒）
4  单测（缺 key 报错 / 规格拒绝 / 轮询超时）
```

**约半天一家，不碰业务代码。**

---

## 一个共同门槛（比开通费更麻烦）

**多数厂商要「公网可访问的素材 URL」，不接受本地文件。**

我们的白模 mp4 在本地磁盘 → 需要：
- 对象存储（OSS/S3）上传，或
- 临时隧道

而 `runtime/publish.py` 里 `TunnelPublisher` 目前是 **`NotImplementedError`** ——
**这一步不补，"素材传不进去"会卡在所有厂商面前。**

## 建议顺序

| 序 | 做什么 | 花钱 |
|---|---|---|
| **1** | 补 `publish.py`（对象存储或隧道），让素材有公网 URL | 0 |
| **2** | 写 `Channel` 骨架 + 单测，**用本地 H3 当被测后端** | 0 |
| **3** | 选一家**有免费额度**的接一次真的（万相/海螺先问） | 0~几元 |
| 4 | Seedance（能力最强）等预算 ≥200 元 | 200 起 |
