# 小剧组 Little Crew — 现状 → 重构后 对照设计

> 用途：开工前把「项目初始形态」与「重构后形态」一次讲清，逐维度对照，作为验收依据。
> 前置：`01-usage.md`（实测基线）、`02-refactor-plan.md`（方案与风险）。
> 已定：前端路线 **B（前后端分离，分两刀走）**；导演台形态 = **ComfyUI 式节点画布**。

---

## 0. 一句话转变

> **把「13 个职业页面 + 全页跳转」换成「一张可编排的节点画布 + 局部执行」。**

| | 现在 | 重构后 |
| --- | --- | --- |
| 心智模型 | 「去哪个**页面**看哪个职业」 | 「画布上**连哪些节点**、跑哪条链」 |
| 用户动作 | 点部门页 → 点职业页 → 选终点 → 跑 → 又跳一页 | 从节点库拖节点 → 连线 → 点一次运行 → 看节点逐个点亮 |
| 复用单位 | 页面（含输入区+进度+审核，全是硬编码布局） | 节点 + 可保存的「工程文件」（拓扑 JSON） |

## 1. 核心概念映射（为什么 ComfyUI 模型刚好合适）

你的系统**已经**是「产物在职业之间流动」的结构，只是没有把它画出来：

| ComfyUI 概念 | 小剧组对应物 | 现有数据来源（已存在，无需新造） |
| --- | --- | --- |
| 节点 Node | **职业/环节**（13 个） | `app/core/org.py:ROLE_ORG` |
| 输入/输出端口 Port | **产物字段** | `state.py` 的 20 个 key（如 `script`/`storyboard`/`images`） |
| 连线 Edge | **数据依赖**（谁产出、谁消费） | 各 Agent 的 `run(state)` 读哪些 key、返回哪些 key |
| 节点参数 Widget | 该环节的配置（模型/步数/是否人工审核） | `runtime_settings` 的 **职业级覆盖**（`llm_provider_writer` 等） |
| Run 按钮 | 执行整条链 | `task_runner.start_run` + 确认点 |
| 节点进度/预览 | 阶段状态 + AI 思考 + 产物缩略 | `phase` / `thinking_log` / `payload` |
| 工作流 JSON 存取 | **可保存/复用的编排方案** | `seed` + `start_stage`/`end_stage`/`enabled_checkpoints` |
| Queue/执行队列 | 任务队列（含逐镜重排） | 现有 `_JOBS` + `_retry_progress` |

**这就是为什么这个方向是对的**：后端跑的就是一张 DAG（LangGraph `StateGraph`），
只是现在拓扑**写死在代码里**、前端**画不出来也改不了**。重构 = 把这张图**暴露成可编辑画布**。

```
│   · 文学策划  │   │ ● 已完成  │   │ ● 已完成  │   │ ● 运行中  │    │ 模型: local    │

│   · 剪辑指导  │                  └──────────┘        │          │ [测试通道]     │
│   · 场记      │                       ┌──────────────▼───────┐  │               │
│ ▸ 技术制作部  │                       │  一致性审查（自动）    │  │ 产物预览       │

│   · 摄影师    │                       ┌──────────▼───────────┐  │ │  S1-01.png│ │

│   · 发行总监  │                                                │               │
├──────────────┴────────────────────────────────────────────────┴───────────────┤
│ 进度：①策划 ②编剧 ③剧评[待审] ④资产 ⑤分镜 ⑥节奏 ⑦场记 ⑧提示词 ⑨画面 ⑩质检 ⑪聚合 │
└───────────────────────────────────────────────────────────────────────────────┘
```

**四个区**：
- **左侧节点库**：13 个职业按 5 部门分组，**按需拖到画布**（这就是你要的「按需提取」）。
- **中间画布**：节点块 + 连线；节点上直接显示状态（待运行/运行中/待审核/已完成/失败）
  与产物缩略，点节点展开详情。
- **右侧属性面板**：该节点的**职业级配置**（模型/步数/尺寸/是否人工审核/重试上限）——
  直接对应现有 `runtime_settings` 的职业覆盖能力，无需新机制。
- **底部流水线进度条**：等价于现有 `_console` 的 12 环进度，但由画布拓扑派生。

## 3. 逐维度对照表（重构验收清单）

| 维度 | 现在（实测） | 重构后 | 验收方式 |
| --- | --- | --- | --- |
| **形态** | Streamlit 多页：1 主页 + 13 职业页 + 5 部门页 + 3 其它 | 单一导演台（SPA）+ 可存取工程文件 | 只有 1 个入口 URL |
| **导航** | 侧边栏被 `display:none` 隐藏，手写按钮 + `st.switch_page` 全页跳转 | 画布内操作，无页面跳转 | 全程不刷新页面 |
| **职业** | 1 职业 = 1 个 `.py` 页面（如 `pages/01_策划总监.py`） | 1 职业 = 1 个**节点组件**，从节点库拖入 | 节点可增删而不改路由 |
| **流程编排** | `start_stage`+`end_stage` **单段**，每次运行在一个职业页里选终点 | 画布 DAG **多段/分支**，可保存复用 | 能连出「先出资产、再挑 3 镜重拍」并保存 |
| **拓扑权属** | 写死在 `main_workflow.build_graph()`（23 节点硬编码） | 由注册表 + 画布拓扑生成 | `grep` 无第二处阶段顺序定义 |
| **取数粒度** | 每次拉**整个 payload**（20 键含全部 images/角色/场景） | 按面板/节点**切片取数** | 单节点只请求自己的产物 |
| **刷新** | 每次交互**整页 rerun**；质检页靠 `time.sleep(1.2)`+`st.rerun()` 硬刷 | **SSE 推送**，节点局部更新 | 运行中只有运行节点在动 |
| **状态源** | `MemorySaver`（进程内存）+ `sessions.status` **双写易不一致** | `SqliteSaver` 持久化 + 状态机单源 | 重启后 `resume` 续跑不重放（§01-usage 6.1） |
| **阶段语义** | 跳过/完成混淆，进度会陈旧停在上一环 | `pending/running/done/skipped/stale/failed` | 跳过节点显示为「跳过」 |
| **数据模型** | `storyboard/prompts/images` 三数组靠 `shot_id` 隐式对齐 | 规范化 **Shot 实体** | 任一处漏项不再错位 |
| **人工确认** | 整页 interrupt + 弹内容；9 个确认点硬编码 | 节点级「待审核」徽标 + 内联 approve/redo/back | 画布上直接审 |
| **provider** | `image.py` 里 4 个 `if provider ==` 分支；列表 3 处重复 | provider 注册表，`local` 为标准实现 | 新增 provider 不改核心 |
| **配置** | 设置页按职业列出；与 `.env.example` 不一致 | 属性面板 = 注册表驱动，单一数据源 | 三处列表自动一致 |
| **产物归档** | CLI 路径落 `_global/no-session-*/`（缺陷） | 统一 `<uid>/<部门>/<职业>/<会话>/` | `run_demo` 也落对 |
| **部署** | Streamlit 8501 + uvicorn `--reload` | 前端静态产物 + FastAPI（多 worker 需 Job 表化） | 单命令起、可多 worker |

## 4. 导演台里的一天（典型操作流）

1. **拖**：从左侧拖出 `策划总监`，输入一句话创意。
2. **连**：拖出 `编剧` `角色设计师` `场景设计师` `分镜师` `技术指导` `摄影师` `质检总监`，连成链。
3. **配**：在 `摄影师` 节点右侧把模型设为 `local`（零成本）、是否人工审核勾上；`质检总监` 的重试上限设 3。
4. **跑**：点 ▶ 运行。节点依次点亮，产物缩略直接出现在节点上。
5. **审**：`文学策划` 节点亮起「待审核」→ 在节点上直接读剧评 → `redo` 或 `approve`。
6. **重拍**：跑完后在 `质检总监` 节点看到低分镜头 → 勾选 S2-01、S3-04 → 只重排这两格。
7. **存**：`保存工程` → 得到一份拓扑 JSON，下次换题材直接复用这条流水线。

> 这套流程里的**每一步后端都已具备**（确认点、精确重排 `retry_shots`、职业级模型覆盖、
> `seed` 续跑），重构主要是**把它们从「页面之间的跳转」变成「画布上的操作」**。

## 5. 后端要补的三件事（增量，不是重写）

画布比现有前端多出的能力，需要后端配合：

| 能力 | 现状 | 需要补的 |
| --- | --- | --- |
| **画布拓扑 → 可执行图** | 图写死在 `build_graph()` | 由注册表**动态生成** `StateGraph`（按拓扑哈希缓存编译结果） |
| **拓扑校验** | 无（阶段顺序由代码保证） | 服务端校验：数据依赖是否满足、是否有非法环/跨阶段倒置，**返回可读错误** |
| **工程文件** | 只有 `seed`/`start_stage`/`end_stage` | 拓扑 JSON 的保存/读取（节点/连线/参数） |

⚠️ **必须说清的一点**：ComfyUI 允许任意连线，但我们的节点**有数据契约**（`分镜师` 没有
`storyboard` 输入就跑不了）。所以画布自由度限定为：
**节点可增删、可重排、可分组、可存拓扑；连线必须满足产物依赖。**
画布不是「随便连」，而是「把已有依赖画出来并允许编排区间」——这样才可执行、可复现。

## 6. 明确保持不变的（降低重构风险）

- **LangGraph 内核**：25 节点、HITL `interrupt`、`Command(resume=)`、`seed` 跳过机制全部保留。
- **13 个 Agent 的 `run(state) -> dict` 契约**：内部实现不动，只被新拓扑调度。
- **9 个人工确认点的语义**（approve / redo / back / content 编辑）。
- **外部 provider 协议**（DashScope / MiniMax / Replicate / local-gen 的 HTTP 细节）。
- **设计系统**：`_styles.py` 的 Sentry 配色与字体（midnight violet + electric lime + Rubik）
  **可直接搬到新前端**，视觉连续性不丢。
- **数据表结构**：先只做投影层，不删列、不迁移历史 payload。

## 7. 两刀怎么切（对应已定的路线 B）

| | 第一刀：后端服务化 | 第二刀：导演台 |
| --- | --- | --- |
| 内容 | 注册表、状态机（SqliteSaver）、切片/SSE API、provider 抽象、拓扑校验、工程文件 | 画布前端、13 个节点组件、属性面板、编排与保存 |

| 验收 | 6+ 回归测试全绿；`/api/registry` 与切片 API 可用；重启续跑不重放 | 画布能连出完整链并跑通一次创作；工程可存可复用 |
