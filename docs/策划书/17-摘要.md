## 摘要

**小剧组 · Little Crew** 是一个基于多智能体协作的 AIGC 漫剧（动画短剧）生成平台。
它以 **ComfyUI 的节点化架构与 API 为执行底座**，在其上自研**统一中间表示（Unified IR）**
与**多智能体协作协议**，目标是让"一集漫剧"从创意到成片实现**可编排、可校验、可复现、
可结算**的工业化生产。

本项目的技术路线建立在一条判断上：**AIGC 漫剧的瓶颈不在生成质量，而在"创意决策"与
"扩散执行"之间缺少共享表示**。创意决策是**语义级**的（角色一致性、剧情节奏、镜头语言），
扩散执行是**张量级**的（节点图、端口类型、采样步数），两者之间没有桥梁。本项目
用统一 IR 架起这座桥，并让多智能体在这座桥上协作。

### 本文的读法（先说清哪部分是"做完了"）

| 你关心什么 | 看哪 |
|---|---|
| **做成了什么、有什么实测数据** | §5.5 ~ §5.9（缓存 / 续跑 / 一集 / 合成 / 门禁） |
| **还有什么没做** | **§5.10 未完成清单** |
| 三个创新点分别实现到什么程度 | §3.1（C1 ✅）/ §3.2（C2 **架构预留**，规则基线替代并实测）/ §3.3（C3 ✅）/ **§3.4（协作可控性，A/B 实测）** |
| 为什么某些事做不到 | §6 硬件约束、§7 风险、§3.8.8 未验证项 |

> ⚠️ **本策划书刻意把「未完成清单」写成独立一节（§5.10），而不是散落在各章。**
> 理由：`✅` 的清单读起来令人愉快，但它**不能告诉你项目离完成还有多远**。
> 一份可靠的交付说明必须同等清晰地列出没做完的部分，
> 否则读者会把「跑通过」误当成「做完了」。
>
> **一句话概括当前落差**：核心链路已端到端跑通（含缓存、续跑、白模空间控制、
> 验收门禁的实测数据），但**对外接口层（`api`/`cli`）完全空白**、
> **创新点 C2 定为「架构预留」**（规则基线已替代并实测，训练因样本量不足不做）、
> **角色一致性的图像层未打通**。
