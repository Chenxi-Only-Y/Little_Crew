> **本节是"缺口清单"，不是"成果汇报"。**
> 它的用途是让人一眼看清**哪些已经能跑、哪些被什么卡住、下一步该动哪里**。

### 5.8.1 先厘清一个概念：角色资产是「两层」，不是一件事

规划文档 §410 的 `bindings` 里，一个角色要装**三样**东西：

```jsonc
"CHAR-0007": {
  "anchorSet": "assets://char/CHAR-0007/anchors/v3",   // 锚点图集（图片）
  "loraFile": "linwan_v3.safetensors",                 // LoRA 权重（文件）
  "embeddingId": "emb_8f21..."                          // 嵌入（向量）
}
```

**这三样都是「图像侧资产」。** 而"角色设计"这个环节应当产出**两层**：

| 层 | 内容 | 谁产 | 本机可行性 |
|---|---|---|---|
| **文字层** | 角色的**可复现外观描述**（发型/发色/服装/体型/标志特征） | 角色设计师（LLM） | ✅ **可以** |
| **图像层** | **锚点图集**（1~3 张） | 图像生成 | ❌ **本机不行**（见 5.8.3） |

**顺序固定**：图像层需要文字层作为输入 —— 否则生成的每张锚点图之间就不一致，**锚点本身失去意义**。

> **常见误解**："我有角色资产设计" ≠ "我有锚点图"。
> 前者是**装载结构**（已有），后者是**结构里的内容**（没有）。

### 5.8.3 关键发现：本地参考图**架构上可行**（此处修正一处此前的错误判断）

`comfy_extras/nodes_zimage.py` 的 `TextEncodeZImageOmni` 实现：

```python
if image_encoder is not None:
    encoded_images.append(image_encoder.encode_image(image))   # 路径一：CLIP-Vision
if vae is not None:
    ref_latents.append(vae.encode(image))                      # 路径二：VAE 参考潜变量
```

**两条参考路径，且本机 VAE 已有（0.16 GB）。**

而 DiffSynth 的官方训练脚本 `Z-Image-Omni-Base.sh` 引用了：

```
Tongyi-MAI/Z-Image-Omni-Base:transformer/*.safetensors
Tongyi-MAI/Z-Image-Omni-Base:siglip/model.safetensors      ← SigLIP 视觉编码器
```

脚本中另有被注释的 **"Image(s) to image training"** 段落，带 `--data_file_keys "image,edit_image"`。

> ⚠️ **此处修正本策划书早期版本的一处判断失误。**
> 早期版本称"图像条件能力在本地是**架构级缺失**"——**这个结论是错的**。
> 犯的错是把「**我们的文本编码器是纯文本的**」说成了「**架构不支持**」。
> 正确的表述是：**现有 checkpoint 是纯文本版，换成 Omni 版即可获得参考图能力。**

**同时必须标注不确定性**：

| 项 | 状态 |
|---|---|
| `Z-Image-Omni-Base` 被官方脚本引用 | ✅ 证实 |
| 它**公开可下载** | ❌ **未能证实**（HF 404 / ModelScope API 404） |
| 可能原因 | 尚未发布 / 已改名 / 需要授权 |

### 5.8.5 长期解：LoRA（**不是项目职责，是外部资产**）

**定位说明**（这一条对答辩很重要）：

| | LoRA **训练** | LoRA **使用** |
|---|---|---|
| 是不是项目一部分 | ❌ **不是** | ✅ **是，且是刚需** |
| 在项目里是什么 | **外部制作活动** | **平台必须支持的一种资产** |
| 类比 | 相当于请人画角色设定图 | 相当于平台支持导入那张设定图 |
| 现状 | 无任何约定 | ✅ 契约/节点/参数映射/降级路径全就绪（见 5.8.2 的 2~3 项） |

**类比 Blender**：平台不实现 Blender，但调用它。**LoRA 训练同理。**

**本机 vs 租用 GPU**：

| | 本机 | 租用 GPU |
|---|---|---|
| Z-Image LoRA | ❌ 22.93 GB fp32 > 15.8 GB 内存 | ✅ 可行 |
| SDXL LoRA | ✅ 6.46 GB 可训（但**画质与中文双退步**） | ✅ 可行 |
| 成本 | ¥0 | **¥5~20 / 次** |

**推荐顺序**：**平台侧先完成"支持 LoRA 资产接入"，租 GPU 留作后续** —— 租来的只是**一个权重文件**，不需要平台改任何代码。

**⚠️ 循环依赖**（必须显式记录）：

```
要训角色 LoRA   →  需要「同一角色的 20~30 张图」
                        ↓
              而现在恰恰生不出同一角色的多张图
                        ↓
                    ← 循环
```

**破环只有三条**：① 真人照片（若有原型）；② **云端 API 参考图生成训练集**；③ 人工画。

#### ⚠️ 曾以为找到了"第四条路"，实测**否证**（2026-10-12）

`local-gen` 的 Z-Image 支持 **img2img**（`input_image_path` + `denoising_strength`）。
设想是：用一张已生成的图当参考，低强度重绘 —— 若能产出**同一角色的不同姿态**，
就能**自举出训练集**，不需要任何外部资源。

**实测结果：锁得住角色，但产不出多样性。**

| 项 | 实测 |
|---|---|
| 机制是否可用 | ✅ 服务端确实切到 `zimage-dif` 引擎走 img2img |
| 单张耗时 | **240 / 267 / 398 秒**（`denoising_strength=0.35`） |
| 角色是否锁住 | ✅ 三张的发色/瞳色/服装/脸型一致 |
| **姿态是否变了** | ❌ **几乎没变** —— 同姿势、同构图、同表情，只有背景细节与微光不同 |
| L2 相似度 | **0.990 ~ 0.9999**（对照：真机同集不同镜均值 0.888） |

**结论**：`denoising_strength=0.35` **太保守** —— 它把构图与姿势一起锁死了。
而训练集需要的是"**同一角色的 20~30 张不同姿态**"，不是 20~30 张几乎一样的图。

#### 2026-10-16 补测：**高强度同样无效，这条路彻底否证**

上面曾留了一句"下一步把强度提到 0.55~0.75"。**那一句已被证伪，不要再去试。**
依据是 `local-gen` 自己的实测记录（`HARDWARE.md` 与 local-gen 技能文档，
比"提强度"这个设想更早、更全）：

| `denoising_strength` | 提示词要求 | 实测结果 |
|---|---|---|
| **0.40** | "坐在咖啡馆窗边、暖色光" | ❌ **构图与背景原封不动**，场景要求被完全忽略 |
| **0.70** | "全身、走在秋天街道、**侧面视角**、回头" | ⚠️ 背景变成了街道 ✓，**但仍是正面特写** —— 没有全身、没有侧面 |

**根本原因**（这才是要记的东西）：

> **img2img 锁的是「这张照片」，不是「这个角色」。**
> 构图、机位、景别、脸被绑成一个**不可拆的整体**。

它从**同一张图的潜变量**起步，所以**空间布局在结构上就被锚住了** ——
提高强度只是"重绘得更狠"，**改不了潜变量里已经固定的空间布局**。
所以强度不是杠杆，**调它没有出路**。

**零成本旁证**（项目内既有的输入/输出对，denoise 0.5，2026-10-06）：

```
i2i_input.png -> i2i_output.png
  肉眼：脸一致；衣服 纯白 -> 红白碎花；项链 银 -> 金
        但姿势、构图、机位**完全没动**
  L2 量化：similarity 0.9939 · layout 0.9996 · palette 0.9969
```

`layout 0.9996` 是决定性的 —— 对照 **构图水平移 15% 只有 0.7940**。
**构图一动没动。**

**所以：**

| | |
|---|---|
| ✅ img2img **能做** | **同机位、同景别的连续镜头**（对话正反打、同场景多句台词）；换服装 / 表情 / 背景 / 光线 |
| ❌ img2img **做不到** | 近景→全景、正面→侧面、站→走 |

**跨机位角色一致性要 i2L / IP-Adapter / LoRA**，而本机**三者都没有可用实现**
（Z-Image 无官方 IP-Adapter 权重；LoRA 训练需 22.93 GB fp32 底模 > 本机 15.8 GB 内存）。

> **真正的解法在项目里本来就有，只是分工不同** —— 见 §5.8.4 开头那句：
> **参考图锁「长相」，白模锁「空间」，二者叠加才是完整方案。**
> img2img 的错误在于**让"参考图"去兼顾"空间"**，所以两边都不彻底。
> 空间归 **ControlNet + 白模**（已跑通），长相归参考图 —— **互补，不是替代**。

> 顺带一个副产品发现：**L2 描述子对"三张几乎是同一张图"给出 0.99+**。
> 这是它该有的行为（它测的是整体一致性），但也再次说明
> **它不能替代身份度量** —— 三张连姿势都没变的图，它无法指出这一点。
> （本次 `layout 0.9996` 倒是说明：**分维比总分有用** —— 总分 0.9939 看着"很像"，
> 而 layout 维单独看才知道"构图没动"。）
