## 五·九、验收门禁的实测（M5）

### 结果

```
合格产物 6 个：正确放行 6，误杀 0    -> 误杀率 0.0%
注入缺陷 8 个：拦下 8，漏放 0       -> 拦截率 100.0%
精确率 100.0%
```

样本取自**真实产物**（`outputs/episode_E100/` 的生成图，832×480）；
缺陷由 8 类真实故障注入构造。证据见 `research/review-evidence/`。

### 三层把关的落点

| 层 | 机制 | 状态 |
|---|---|---|
| **L1** | **确定性断言算子** | ✅ 10 个算子，`review/ops.py` |
| **L2** | 一致性嵌入（看跨镜漂移趋势） | ⬜ 未实现 |
| **L3** | 跨模型族盲读（生成方 ≠ 审核方） | ⚠️ 机制在 `agent/orchestrator.py`，**仍未接进门禁报告** |

### 两条反自我签收的守卫

**这是 C3 的核心，也是本项目与"模型自评"路线的根本差别。**

#### ① 缺观测 ≠ 通过

注入的 8 类缺陷里，有一条是"**观测值缺失（未测）**"，门禁判 `RETRY`。

若把"没测"当成"通过"，就等于**放行了从未被检查的约束** ——
这是自我签收的变体，而且更隐蔽：报告上看起来一切正常。

#### ② 判定不可信 ≠ 产物不合格

门禁是**三态**的，不是二态：

| 结论 | 含义 | 处置 |
|---|---|---|
| `KEEP` | 全部硬门禁通过 | 交付 |
| `RETRY` | **产物**不合格 | 带返工指令回去重做 |
| `ESCALATE` | **判定本身不可信** | 升级人工 —— **不给返工指令** |

实测：约束引用未知算子 -> `ESCALATE`（而非 `RETRY`）。

合并后两者的后果：判定不可信时也去返工 -> 白烧算力且下次依然不可信；
产物不合格时去叫人 -> 人被迫做机器能做的事。

**`ESCALATE` 优先于 `RETRY`** —— 连结论都不该信时，更不该拿它驱动返工。

### ⚠️ 实现过程中犯的一个错（记录，因为它正是 C3 要消灭的模式）

第一版里，约束引用未知算子时 `evaluate_one` 返回 `None`，
于是该约束**从报告里彻底消失** —— 一份"4 条约束"的报告只列出 3 条，
而缺的那条恰是**没被检查**的那条。

> **C3 要消灭的模式，出现在了 C3 自己的实现里。**

已修：无法判定的约束**仍产出断言记录**，标注 `evaluated: False` 与原因。
自检里加了 `E6/E7` 两条断言锁住它。

### 一次夹具错误（记录以免重犯）

第一版测量报出 **50% 误杀率**。**那是夹具的错，不是门禁的错。**

我把分辨率不同的对照拼图（1050×230 等）也当成"合格产物"，
再喂给一条要求 832×480 的约束 —— **门禁拦它完全正确**。

> **门禁的职责是「按声明的规格判定」，它不该猜哪张图算合格。**
> 基准由调用方给，给错了是调用方的错。

### 已接进流水线（2026-10-12 补充）

门禁从"独立可调用的判定层"变成**流水线的一环**：渲染后、合成前判定，
结论进交付证据链，且 **`ok` 会因门禁而变 `False`**。

**真机实测（ComfyUI + 白模控制，3 镜）**：

```
门禁计数: {'shots': 3, 'kept': 3, 'retry': 0, 'escalate': 0, 'skipped': 3}
具备的观测能力: ['bytes', 'characterCount', 'height', 'name',
                'plannedDurationSec', 'width']

逐镜裁定:
  SH-E100-001-001  KEEP  [v] cr_res_…   resolution_matches  {width:832, height:480}
                         [v] cr_cast_…  count_at_most        {characterCount:2, max:3}
```

**分辨率是真的量出来的** —— 从 `{文件名: bytes}` 里的**内存字节**解析 PNG 头，
而不是读产物引用上的字段（那些字段实测为空）。

#### 为什么"接进去"比看起来难：一个反复出现的静默失效

接入过程中，**同一个失效模式现身了两次**：

| 次 | 原因 | 症状 |
|---|---|---|
| 1 | 观测提取只按 `ArtifactRef` 对象读 | 引用上的 `width`/`bytes` 为空 → 分辨率类约束**全部被跳过** |
| 2 | `_run_gate` 用 `list(o.artifacts)` 只取了**键** | `CacheOutcome.artifacts` 是 `{名字: bytes}`，取键就丢了字节 → 同样的症状 |

**共同点：没有任何一处报错。** 门禁看起来接了、报告看起来正常、`ok=True` ——
但它实际上**一条约束都没检查**。

唯一能抓到它的是"断言它**确实执行了**"的测试（`G3` / `G14`）。
这也是本项目反复出现的那个模式的又一例：
**凡是"本地看不出、跑起来也不报错"的缺陷，只能靠"断言机制真的生效"来抓。**

#### 约束的强制级别：算子实现了，就该升 hard

| 约束 | 级别 | 理由 |
|---|---|---|
| 分辨率 / 时长 / 角色数 | **hard** | 确定性能判，且不满足确实不该出片 |
| 身份相似度 | **soft** | 本机没有人脸/嵌入模型，**算不出来**；标 hard 会让每镜都升级人工 |

早期把所有约束标 `soft`，理由是"断言算子未实现" —— 现在算子已实现（10 个），
**继续标 soft 就是自己放弃了门禁的阻断能力**。

### 5.9.3 L2 一致性嵌入：能做与不能做

**结论先写**：它是一个**粗粒度一致性描述子**，不是身份度量。
正因如此，它的强制级别是 **`audit`**（如实记录，不阻断）——
这个决定有实测依据，不是保守。

#### 之前的状态

`ops.py` 里有 `identity_similarity` 与 `pairwise_similarity` 两条算子，
它们只负责**比阈值**，文档写明"相似度由谁算是调用方的事"。

**而那个"调用方"此前不存在。** 于是本机实测里这两条约束
**永远被判"缺观测 similarity"而跳过** —— 跨镜角色一致性**没有任何度量手段**。

#### 四维正交分解

| 维度 | 负责 | 返工方向 |
|---|---|---|
| `palette` | 色相分布（色彩的"身份"） | 改风格/提示词配色 |
| `layout` | 8×8 网格亮度布局（构图） | 改机位/构图 |
| `lighting` | 明度分布（曝光） | 改打光参数 |
| `richness` | 饱和度分布（色彩浓度） | 改饱和度/风格强度 |

**为什么要拆四维**：门禁要回答"**是哪一维不一致**"，那直接决定返工方向。
答错方向等于白跑一轮返工。

**受控退化实验（12 项）归因 12/12 正确**：

| 退化 | 最弱维 | 退化 | 最弱维 |
|---|---|---|---|
| 色相 +10/25/60° | `palette` | 去饱和 0.5 / 0.9 | `richness` |
| 亮度 ×1.15 / ×1.40 | `lighting` | 构图移 5% / 15% | `layout` |
| 局部崩坏 10% / 30% | `palette` | 基准 | 全为 1.000 |

#### ⚠️ 它**不能**判身份 —— 这是硬的边界

| 数据集 | 观测区间 |
|---|---|
| **同一集、同一管线**（9 张真实产出） | **0.80 ~ 1.00**（均值 0.888） |
| 跨批次混比（34 张） | 0.66 ~ 1.00（均值 0.833） |

**关键事实**：同一角色在**不同构图**下就落到 0.66，
而**完全不同的场景**也在同一区间。两者**重叠** ——
所以**没有任何阈值**能把"角色漂移"与"换了景别"分开。

**中心裁剪试过了，没用**：

| 取区 | 均值 | 最低 |
|---|---|---|
| 整帧 | 0.6165 | 0.3592 |
| 中心 60% | 0.6003 | 0.3917 |
| 中心 40% | 0.5848 | 0.4005 |

裁剪几乎不动 —— 说明**不是背景淹没**，而是"整图统计量"
这个度量本身答不了"是不是同一个角色"。

**所以它测的是「整体像不像同一场戏」。**

#### 为什么标 `audit` 而不是 `hard`

| 阶段 | 级别 | 理由 |
|---|---|---|
| L2 之前 | `soft` | 算子未实现，标什么级别都无代价 |
| L2 之后（第一版） | `soft` | 能算了，但不该阻断 |
| **定稿** | **`audit`** | 能算，**但测的不是身份** —— "不合格"这个结论不成立 |

**明确不做的事**：不把它改标 `hard` 来"显得门禁更严"。
那样做的后果是**每一镜都被判不合格**，而真正的问题是**度量能力不足**——
**把能力缺失伪装成"发现了缺陷"，比不做度量更糟。**

阈值取 **0.70**：同集同管线的真实分布最低是 **0.801**，
所以正常变化不会误报；灾难性退化（局部崩坏 30% → 0.78）会告警。
**它是告警线，不是通过线。**

#### 一次真实的方法学修正

最初用**直方图交集**，它在受控退化下暴露了严重缺陷：

| 画面 | 饱和度直方图 | 交集 |
|---|---|---|
| 原图 | `[0,0,0,1,0]`（全在桶 3） | — |
| 轻度去饱和 | `[0,0,0,1,0]` 或 `[0,0,1,0,0]` | 0 或 1 |
| 重度去饱和 | `[1,0,0,0,0]`（全在桶 0） | **0.00** |

**两幅"中等程度不同"的图被判成 0 相似度**，而"完全一样"的是 1 ——
中间没有过渡。因为真实图像的统计量高度集中，微小数值平移就跨过桶边界。

改用 **EMD（推土机距离）** 后，分布**平移**只产生小的距离，
只有分布**形状真的变了**才会拉开 —— 12 项归因才全部成立。

> **教训**：直方图比较里"交集"是常见做法，但它隐含假设
> 「桶是独立类别」。对**有序**统计量（色相/明度/饱和度都有序），
> 那个假设是错的 —— 该用知道"相邻桶很近"的距离度量。

#### 仍未做的部分

| 项 | 现状 |
|---|---|
| **阈值未在缺陷集上验证** | ⚠️ 0.70 来自"正常分布的下界"，**不是**"缺陷分布的上界" |
| **不参与返工闭环** | ⚠️ `audit` 级不阻断，也就不触发返工 |
| **只支持 PNG** | ⚠️ 其它格式走 `consistencyUnavailable` |
| **判身份** | ⚠️ 需人脸/身份嵌入模型，本机没有 |

### 5.9.2 返工闭环：门禁从「报告」变成「机制」

**链路**：

```
渲染 -> 门禁判 RETRY -> 有可应用的动作 -> 改 IR -> 只重跑那几镜 -> 复检
                        ^                                        |
                        +---------- 最多 max_repair_rounds 轮 ----+
```

**实测**（自检 H1）：

```
首轮：门禁判 RETRY（分辨率 32x24 != 要求 64x48）
      -> 返工动作 ir.set_params(n_latent, {width:64, height:48})
      -> **只有那一镜**重跑（提交 3 次 = 首跑 2 镜 + 重跑 1 镜）
      -> 复检 KEEP
结果：ok=True
```

> **门禁原本"知道哪里错了"但"不知道该改什么"** ——
> 它产出的是给人看的句子，机器读不懂。
> 所以缺的不是判定，而是**可执行的修正**。

#### 为什么两种表达都要

| 只有句子 | 只有动作 |
|---|---|
| 循环没法执行 | 报告读不懂，人无法判断该不该接受 |

所以每个失败断言同时产出 `repairs`（句子，进报告）与
`repair_actions`（结构化，进循环）。

#### 只有 3 类约束可自动修（如实标注）

| 可自动修 | 不可自动修（附原因） |
|---|---|
| 分辨率 `ir.set_params` | **削减角色** —— 创作决策（删谁/合镜/拆镜），不该由规则做 |
| 宽高比 `ir.set_params` | **身份相似度** —— 需锚点图或 IPAdapter 权重，本机都没有 |
| 时长 `shot.set_duration` | **文本差异** —— 需按剧本原文重写，属生成决策 |
| | **文件过小** —— 需查编码链路，不是参数问题 |

**"不可应用"必须如实标记**：假装可修会让循环白跑 N 次然后失败，
而真正的问题是**能力缺失**。

#### 三道防烧 GPU 的闸

| 闸 | 作用 |
|---|---|
| `max_repair_rounds` | 硬上限。没有它，门禁不退让就会无限重跑 |
| `repairable_shots()` | 动作**全不可应用**的镜头不重跑 —— 跑了也是同一张图 |
| **IR 哈希必须变** | 没变就是命中缓存，重跑等于空转 |

**第二道最有价值**：实测 `count_at_most(max=0)` 这种"能算但修不了"的约束，
循环**明说**"没有可应用的动作（能力缺失，不是参数问题）—— 不重跑，如实上报"，
而不是白跑三轮。

#### 三条铁律

| # | 铁律 | 理由 |
|---|---|---|
| 1 | 动作**必须改变 IR 的哈希** | 否则重跑命中缓存拿回同一张图，循环空转 |
| 2 | 修不了的**如实标记** | 假装可修 = 白烧算力，且掩盖真正的能力缺失 |
| 3 | 动作是**对 IR 的编辑**，不是对图的编辑 | 平台的可复现性建立在"IR 是唯一真相"上；改图会绕开哈希链 |

#### 仍未做的部分

| 项 | 现状 |
|---|---|
| **不可自动修时不升级人工** | ⚠️ 只如实报 RETRY；接进 `agent` 的升级流程是下一步 |
| **返工不回退到分镜层** | ⚠️ 只重跑渲染；若缺陷在分镜（如角色数超限），当前不会回退 |
| **没有"修完仍不过"的二次升级** | ⚠️ 上限用尽后停在 RETRY |
| **返工次数不成本核算** | ⚠️ 未计入 `secondsSaved` / 成本报告 |

### 已知限制

| 项 | 现状 |
|---|---|
| **相似度类算子** | ✅ **已参与测量**（alpha.27 的 L2）。但它是**粗粒度一致性描述子，不是身份度量** —— 同角色不同构图与不同场景的分数区间**重叠**，见 §5.9.3。因此只标 `audit`，不阻断 |
| 缺陷样本量 | 8 类。足以证明"能拦"，**不足以给出统计置信区间** |
| **返工闭环已闭合** | ✅ 门禁判 RETRY -> 改 IR -> **只重跑那几镜** -> 复检（见下方 §5.9.2）。**但只有 3 类约束可自动修**，其余动作如实标为不可应用 |
| **`duration_within` 在图像阶段恒被跳过** | ⚠️ 图像没有时长 —— 该约束要到视频阶段才可判定。**被显式记录**为跳过，不是静默通过 |
| **`engine_resolution` 必须与实际产出一致** | ⚠️ 不一致会让**每一镜都被判不合格**（实测：夹具产 64x48 而约束写 832x480 → 12 镜全 RETRY）。门禁没错，是约束没反映真实规格 |
