## 八、局限与负结果

> **这一章写的是"我们哪里不行"。**
> 不是流程图上的风险，是**实测撞出来的**、**写进 CHANGELOG 的**、**没有事后抹掉的**。
>
> 写它的理由很简单：**一份只写成功的方案，评审只需问一句就塌了。**

### 8.1 结论本身可能是错的（两条标「待重做」）

| 结论 | 问题 | 重做需要 |
|---|---|---|
| **返工多数让质量变差**（改善 3 / 变差 5 / 没动 2） | **n=10 太小**；且只记分数、没记退回指令的文本 → 无法归因 | n→20~30；同时记录每次退回的**原因文本**，看"指令质量"与"改善/变差"是否相关 |
| **白模在强度 1.0 时会弄坏画面**（土坡占 2/3） | **只有一镜、一个提示词**；且该镜提示词本身把场景写成"山坡"，**混杂变量未排除** | 3~5 个不同场景的镜头 × 三档强度，并先排除提示词场景冲突 |

> **两条都保留全文、标题标「待重做」，不删。**
> 删了，等于把"我们量过、发现不对"这段也删了 —— 那才是答辩最容易被追问的地方。

### 8.2 被实测否定的假设（三条）

| 假设 | 当初为什么信 | 怎么被否的 |
|---|---|---|
| **`set` 为空 → 模型乱编环境** | 土坡看起来像"空地被自由发挥" | 加两个道具（花垄 + 岩石）后画面几乎不变（12.99% vs 13.27%），**三次否定** |
| **紫色占比可衡量"花田是否主体"** | 直觉上紫色 = 薰衣草 | 视觉最差的 1.0 组反而紫色最多（6.22%）—— 土坡金黄、饱和度高 |
| **地平线行可衡量"构图是否听白模"** | 假设"天空低饱和、地面高饱和" | 1.0 那张上半是金黄土坡（高饱和），**前提崩了**，测到的是另一个边缘 |
| **「花田是否主体」可当通用判据** | 直觉上这集拍的就是花田 | **镜 2 拍的是倒地的旅人** → 该分数恒为 1，A/B 必然打平；**把"测不到"误读成"没差别"** |

> **共同点：三个假设都"看起来合理"，都靠一次实验就否掉了。**
> 所以规则不是想出来的，是**验出来的** —— 这也是为什么 `set` 规则最终没有加进校验器。

### 8.3 三次"系统不稳"，其实是我的观察方式有问题

| 现象 | 第一反应 | 真相 |
|---|---|---|
| `previs` 报告里是 `{}` | "白模失败" | **没绑上实现**，静默早退（已改为带 reason） |
| E701 命中 / E704 不命中 | "判定不可复现" | 判定**一直可复现**（两次跑逐镜一致）；是打印前缀和 grep 变了 |
| `scene_check.json` 没生成 | "写盘失败" | **我自己写的 `except: pass` 吞了异常** |

> **教训：在断言"系统有问题"之前，先让结果可核对。**
> 三次全是我自己的观察方式错，而每次都差点变成一条"要修的 bug"。

### 8.4 能力边界（本机实测，不是猜测）

| 边界 | 实测结论 |
|---|---|
| **IPAdapter** | 本机 **没有**（970 节点里无 `IPAdapter*`）→ 角色一致性只能走 LoRA |
| **LoRA 训练** | 本机 **跑不动**（fp32 22.93 GB > 15.8 GB 内存）→ 需租卡 |
| **控制图进画面** | 曾经**生成了但一张没进图**（桥接在预演之前 + 渲染入口写死 http），修了 4 轮才通 |
| **整集链路只验过单镜** | 40 镜全量 + 控制图**从未同时跑通过** |

### 8.5 方法学局限（写论文必须标注）

| 局限 | 影响 |
|---|---|
| **E1 未盲判** | 评分者是我们自己，"协作提升"有自评偏倚 |
| **单镜 / 单提示词** | P0-2 的强度结论换一镜可能翻转 |
| **n 普遍偏小** | E3 是 10、E7 是 5 —— 只能看方向，不能下断言 |
| **自动指标不可用** | "构图是否听话"目前**没有**可信的自动指标 |
| **同源审核**（已解决） | 曾是致命缺陷；`alpha.81` 接 GLM 补了第三族 —— 但要写明"曾经没有" |

### 8.6 这条边界之外，我们明确不做

| 不做 | 理由 |
|---|---|
| 自研图编辑器 | 我们的程序不是图（图只是影子）；改影子不改真身 |
| 自研推理补齐控制/参考能力 | ComfyUI 有的能力应当**消费**，不是重造 |
| 本地安装包 / exe 打包 | 8 GB 权重 + CUDA 组合，做出来也维护不了 |
| 为"画质更好"背书 | 模型是用户选的；我们只对一致性、失败率、时长负责 |
