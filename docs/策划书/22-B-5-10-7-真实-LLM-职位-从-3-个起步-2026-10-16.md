排查发现**不是"没写职位"，是中间缺了一段**：

```
models/registry.py:116   api_key_env="DEEPSEEK_API_KEY",   ← 声明 6 处

```

`registry` 声明了模型/端点/路径/请求模板；`http.py` 能发请求、渲染模板、
取响应 —— **但没有人把它们接起来**。协议齐备，只缺中间那一段。

新增 `agent/llm.py`（连接层）与 `agent/crew_llm.py`（职位实现）后：

| 职位 | 模型 | 族 | 实测 |
|---|---|---|---|
| **编剧** | DeepSeek V4（实服务 `deepseek-flash`） | deepseek | 首稿 8 场 1382 字 / 10.9s |
| **剧评人** | 小米 MiMo v2.6 Flash | **mimo** | 逐场报冲突/代价/转折 |

**两者不同族** —— 满足跨模型族盲读的硬要求（见 §5.9）。

#### 实测到的三件事（都值得记）

**① 返工闭环真的工作。** 编剧收到"代价缺失"的意见后，
自述「新增 S03 整场作为代价场：林晚必须亲口说出母亲是自杀的，
并重复那句折磨她二十年的遗言，同时承认自己恨了母亲二十年」——
**是结构级的修改，不是随机重采样**。

**② LLM 剧评人的判断力确实超过正则桩。** 它指出：

> S02 铺设了父亲的强力反对，但 S03 中父亲**完全缺席**，
> 「人群里一阵骚动」之后也无人真正阻拦。全剧最大的外部阻力
> 在关键决定场景里**凭空消失**，"我跟你走"这一行为主打一路顺风。

**这是真的剧作结构问题**，而规则桩的正则（`但|却|然而|甩开|代价|转身`）
读不出散文里的这类缺陷。

**③ ⚠️ 桩审查方与 LLM 编剧天生不匹配。** 这一条是推论，但很确定：
正则表是按"显式连词"设计的，而**越自然的散文越不含那些生硬连词**。
所以存在一个反向激励：

```
编剧写得越好 -> 越匹配不上正则 -> 越被打回
```

混用两者时，编剧改得再对也过不了门禁。**换实现必须成对换。**

#### ⚠️ 尚未打通：分镜规划（如实记录）

剧本闭环现在能跑满 3 轮（225 秒），但 **`分镜：0 个镜头`**。
原因：`storyboard_artist` 仍是规则桩，它按**正则解析编剧的产出**
（`[场N]` 切场、`@角色` 标人物），而 LLM 编剧产出的是
`scenes` 结构化数组 —— **桩读不懂**。

**这不是 bug，是两种产出形态不兼容。** 下一步二选一：

| 方案 | 代价 |
|---|---|
| 把 `storyboard_artist` 也换成 LLM | 又一轮 API 成本；但它本来就是"把场次切成分镜"，适合 LLM |
| 在 LLM 编剧的产出上补一层"渲染成桩认识的文本" | 便宜，但**多一层转换就多一处会漂移的地方** |

**倾向第一种** —— 沿同一逻辑：**换实现要成对换**。

#### ⚠️ 结构性发现：**语义审核方 + 「必须零问题才通过」= 流水线走不动**

把剧评人也换成 LLM 之后，剧本闭环跑满 3 轮仍不通过。排查后确认
**不是模型不行，是裁定规则与审核方类型不匹配**：

```python
class RoundResult:
    @property
    def accepted(self) -> bool:
        return self.verdict is Verdict.PASS and not self.invalidated_reason
```

而 `verdict` 由 `_VERDICT_RANK` **取最严**合并：

```python
_VERDICT_RANK = {PASS: 0, REVISE: 1, REJECT: 2, ESCALATE: 3}
```

问题在于：

> **一个尽责的剧评人几乎永远不会说「完全没问题」。**
> 它总能指出"这里节奏可以更好"。

于是"有意见 → REVISE → 不 accepted"这条链导致
**任何一轮都过不了**，`EpisodeRunner.run` 在剧本阶段就 early return，
**分镜阶段根本执行不到**（这才是"分镜 0 个"的真正原因 —— 不是分镜师的问题）。

**两类审核方被混用了**
----------------------

| 类型 | 例子 | 它说的是 | 该有否决权吗 |
|---|---|---|---|
| **确定性门禁** | 分辨率、时长、角色数、格式 | "**违规**"（客观、可复现） | ✅ **该** —— 违规就是不合格 |
| **语义批评** | 剧评人、文字编辑 | "**可以更好**"（主观、连续） | ❌ **不该无条件否决** |

把它们用同一套"最严合并"规则处理，结果是**用主观意见把客观流程堵死**。

**修法（未实施，需先定口径）**：给语义审核方一个**阈值**，
而不是要求零意见。例如：

| 方案 | 说明 |
|---|---|
| **A** | `total >= 阈值` 且无 `BLOCKER` 级意见 → 通过 |
| **B** | 语义意见标 `advisory`（**只记录、不阻断**），确定性意见才阻断 —— 与 §5.9.3 里 L2 只做 `audit` 的判据**同源** |
| **C** | 结构三要素（冲突/代价/转折）**各自**有明确判定，模型只回答"这一场有没有"，而不是笼统评论 |

**倾向 B + C 组合**：B 让"可以更好"不阻断流程（与已有的 `audit` 级一致），
C 把主观判断收敛成**可判定的问题**（而不是开放式的剧本评论）。

> ⚠️ **这条与 §5.9.3 的判据是同一个道理**：
> **把能力缺失伪装成「发现了缺陷」，比不做度量更糟。**
> 反过来也成立 —— **把"可以更好"当成"不合格"，会让流程永远停住。**

#### 本轮踩的三个坑（都是我造成的，记下来避免重犯）

| # | 坑 | 教训 |
|---|---|---|
| **1** | 返工操作用了 `revise_scene` —— **不在权威表里** | 构造 `RepairHint` 时抛 ValueError，表现成"审核者执行失败"，**乍看像模型的问题**。**权威表要读，不要凭记忆写**；现改为从 `KNOWN_OPS` 推导 |
| **2** | `render_body_template` 把**列表序列化成字符串** | `[{"role":"user"}]` → `"[{'role':'user'}]"`，服务端报 `messages: invalid type`。**模板对、值对、也是合法 JSON** —— 只是语义从数组变字符串，极难归因 |
| **3** | `agent/llm.py` 从 `runtime` 导入 | `agent`(层 6) 不能 import `runtime`(层 8)。**正确的反应不是放宽守卫，而是把东西放到对的地方** —— 两个函数下移到 `models/template.py`（契约的实现在契约旁边） |

#### 跨族检查是**真的会拦**的

`episode_demo --llm` 里加了硬校验：编剧与剧评人用同一个模型时**直接拒绝**，
并打印原因。理由：同族判定会让门禁退化成**自我签收**，
**而且不会报错** —— 静默退化比崩溃危险得多。
