# 调研：多智能体 vs 单智能体，优势到底在哪

> 2026-11-04。**先弄清学界与业界的边界，再谈我们该往哪走。**
> 结论先行：**多智能体的优势是有条件的，而且条件通常不是"分工"。**

---

## 一、文献怎么说

### 1. "增加 agent 数"确实能提升 —— 但靠的是**采样与投票**

[More Agents Is All You Need](https://ar5iv.labs.arxiv.org/html/2402.05120)：
用最简单的 **sampling-and-voting**（多个 agent 各自作答，再投票）就能提升表现，
**增益随任务难度上升**；简单任务上几乎无增益。

> **关键含义：这个提升来自"多采几次再选"，不是来自"角色分工"。**
> **而"多采几次"正是我们要避免的抽卡。**

### 2. 多智能体系统有一套**独立的失败模式**

[Why Do Multi-Agent LLM Systems Fail?（MAST，NeurIPS 2025）](https://neurips.cc/virtual/2025/loc/san-diego/poster/121528)
归纳出三类失败：

| 类别 | 内容 |
|---|---|
| **规格说明** | 任务/角色/输出格式没定义清 |
| **agent 间错位** | 信息传递丢失、指令冲突、职责重叠 |
| **验证与终止** | 没人检查、检查了不采信、停不下来 |

> **这三类失败，在我们项目里全都出现过：**
> 场景越权（规格）、预算被当配额（错位）、PASS 却带 MAJOR issues（验证）。

### 3. "多智能体是否真的有帮助"仍是开放问题

[Do Multi-Agent LLM Systems Actually Help?](https://www.zenodo.org/records/22957165/files/Do_Multi_Agent_LLM_Systems_Actually_Help_Preprint_v1.pdf)
这篇的立场是：**很多报告的增益无法在公平对照下复现。**

### 4. 工程界的主流建议：**先简单，再复杂**

Anthropic 的 [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)（业界广引）主张：
**能用单次调用/固定工作流解决的，不要上多智能体**；
多智能体的代价是 **token 翻数倍 + 调试困难**。

### 5. 也有明确的"赢"的案例

[Orchestrated multi agents sustain accuracy under clinical-scale workloads](https://europepmc.org/article/PPR/PPR1072395)：
在**长上下文、大规模**任务下，编排式多 agent 能**维持准确率**，而单 agent 会衰减。

> **这类赢的共同点：单 agent 会"装不下"或"记不住"。**

## 二、把文献收敛成三个"能赢的条件"

| # | 条件 | 为什么单智能体做不到 | 文献对应 |
|---|---|---|---|
| **① 单 agent 装不下** | 上下文/工作量超出一次调用 | 临床大规模、超长文档 | 5 |
| **② 需要独立验证** | 生产者无法"看不见自己" | 审片、review、事实核查 | MAST 的"验证"类 |
| **③ 任务本身可分解且子任务独立** | 一次调用同时决定多件事会互相干扰 | 软件开发（MetaGPT/ChatDev） | 1 |

**反面：**

| 不满足条件时 | 结果 |
|---|---|
| 任务单点、一次能做完 | **只增加成本，质量无差**（Anthropic） |
| 增益实际来自多采样投票 | **是抽卡，不是协作**（More Agents） |
| 协调没写好 | **失败模式更多**（MAST 三类） |

## 三、对照我们自己的实测

| 我们的实验 | 结果 | 属于哪种情况 |
|---|---|---|
| **分镜 A/B**（有/无导演） | **打平**（29/30 vs 29/30，节奏 4.86 vs 4.56） | **不满足①，也不满足②** → 只增加成本 ✅ 与文献一致 |
| **剧本多轮返工** | 首轮 18% → 最终 29% | 满足②（独立审查）→ **有增益但方差大** ✅ |
| **场景越权拦截** | 真跑 2/3 集开火 | 满足②（上游意图 vs 下游产物）→ **单 agent 结构上没有** ✅ |
| **多视角审** | 违规 30/30 | 满足② → **有增益** ✅ |
| **跨场连续性（场记）** | 实测无矛盾可修 | 不满足①（单场就够）→ **没有收益空间** ✅ |

> **五项实测，与文献给出的三个条件逐条吻合。**
> **这不是巧合 —— 说明我们的实验是可信的。**

## 四、由此得出的定位（写进论文的口径）

> **本项目不主张"多智能体在生成质量上更强"。**
> **本项目主张：在"需要独立验证"的环节，单智能体结构上无法自我检验，**
> **而验证正是交付质量的守门人。**

**具体三条（都有我们自己的数据）：**

1. **越权检查**：下游改了上游要的场景 —— 单 agent 没有"上游意图"这个概念。
2. **多视角审**：30/30 违规拦截，靠的是不同视角互不复述。
3. **返工闭环**：把交付率从 18% 提到 29%，代价是方差大（如实写）。

**不主张的：**

- ❌ "分镜更自然"（实测打平）
- ❌ "画质更好"（白模只改构图不改画质）
- ❌ "多 agent 就一定更强"（文献本身有争议）

## 五、下一步该往哪走（由此确定）

| 方向 | 依据 | 优先级 |
|---|---|---|
| **把"验证"做深**（越权 / 多视角 / 证据链） | 唯一有数据的优势 | **P0** |
| **返工建议结构化**（让第 2 轮就过） | 减少抽卡的正解 | **P0** |
| 分镜分工调参 | 已证无效（打平） | **不做** |
| 场记 / 跨场状态 | 无可修缺陷 | **不做** |
| 多采样投票 | 是抽卡，与目标冲突 | **不做** |
