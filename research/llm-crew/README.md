## ⚠️ `--accept-script` 是什么，为什么用它

**`scriptVerdict: REVISE`（67.9 分，低于通过线 80）** ——
剧本门禁**没有放行**，是 `--accept-script` 强行进入下游的。

**为什么这样做**：本轮要验的是**下游链路**（桥接/编译/出图/门禁/清单），
而"剧本能否过门禁"取决于**阈值标定**（见 `docs/00` §5.10.8）——
那是另一个独立问题。**用一个还在标定的阈值去挡另一个待验的链路，
会让两件事都验不清楚。**

**所以这个开关：**
- 默认关闭，CLI 帮助里明确写"调试用"
- 结果里 `scriptVerdict` **仍如实显示 REVISE** —— 不掩盖"剧本没过"
- **正式跑绝不能开**

| 文件 | 景别/运镜（LLM 自己的分镜决定） | 观察 |
|---|---|---|
| `shot01_full_truck_left.png` | `full` / `truck_left` | 全身、在薰衣草田边走 —— **景别与运镜都兑现了** |
| `shot02_medium_static.png` | `medium` / `static` | 中景、洞穴前 —— **跨镜角色外观基本一致**（暗红发色、深蓝上衣、竹篮） |

**第二张尤其重要**：它证明**外观片段真的并进了提示词**。
在此之前有一个**静默失效**：定妆表识别出 **0 个角色** →
`_with_appearance()` 对认不出的名字静默跳过 →
每镜提示词里**没有任何外观信息**，而**不报任何错、测试也全绿**。

根因：`script_text()` 把 `ScriptDraft` 压成文本时**丢掉了 `characters` 字段**，
而下游 `_characters_of()` 只认 `@名字` 文本标记。
真实 LLM 产出的是结构化列表，于是 0 个。

**已修，并加了 7 条回归测试**（`character_sheet_check` 的 J 段）。
