## ⚠️ `--accept-script` 是什么，为什么用它

**`scriptVerdict: REVISE`（67.9 分，低于通过线 80）** ——
剧本门禁**没有放行**，是 `--accept-script` 强行进入下游的。

**为什么这样做**：本轮要验的是**下游链路**（桥接/编译/出图/门禁/清单），
而"剧本能否过门禁"取决于**阈值标定**（见 `docs/00` §5.10.8）——
那是另一个独立问题。**用一个还在标定的阈值去挡另一个待验的链路，
会让两件事都验不清楚。**

**所以这个开关：**
- 默认关闭，CLI 帮助里明确写"调试用"
- 结果里 `scriptVerdict` **仍如实显示 REVISE** —— 不掩盖"剧本没过"
- **正式跑绝不能开**

## ⚠️ 这一集用了 `--accept-script`

剧本 **58.5 分（REVISE）**，没过 65 的线 —— 与标定实验中约 40% 的自然失败率一致。
`--accept-script` 强行进入下游（`scriptVerdict` 仍如实写 REVISE）。

**为什么仍然有价值**：这一轮验的是"**下游在 24 镜量级上成不成立**"
（缓存、显存、提示词多样性、门禁命中、视频合成），
那是与"剧本能不能过线"互相独立的问题。

## 途中踩到的两件事

### ① local-gen 的推理进程被"窗口关闭事件"杀掉了

第一次跑 24 镜，**24 镜全部 HTTP 500**：

```
forrtl: error (200): program aborting due to window-CLOSE event
```

`/health` 还能回 200（HTTP 壳活着），但出图一律 500 ——
**像"服务在跑"，其实干活的那一半已经死了**。
`[Errno 22] Invalid argument` 是它的表现，不是"提示词太长"或"显存不够"。

重启后单张 20.6s 正常。**运维结论**：这个服务要用分离进程 + 日志重定向跑，
不要挂在会被关掉的控制台窗口里。

### ② 报告把"渲染挂了"报成了"剧本分数不够"

第一版报告写的是 `failure_kind = below-threshold`（剧本分类），
而真正卡住交付的是**渲染服务**。两者该做的事完全不同。

已修：**出图失败优先于剧本分类**（`render-failed`）——
只要有镜头渲染失败，"下一个动作就是查出图"，所以它压过剧本裁定。
剧本的裁定仍在 `scriptVerdict` 里，信息没丢。

## 从画面里看到的两件事（诚实记录）

### ① 提示词以前**没有进证据链**

清单每镜只存了文件名 + 哈希。也就是说：
**能证明"这张图是我产的"，但不能证明"我当初要的是什么"**。
哈希只能验真伪，验不了"要求与实际是否相符"。

已修：`episode.master.json` 的每镜记录新增 `prompt` 字段
（存**并入外观之后**的镜头描述 —— 那是真正决定画面内容的文本）。

### ② 模型会画"没被要求的人"

`S01-001` 的清单写着 `characters: ["少女"]`，画面上却是一个少女**和一个男人**。

这一镜的提示词当时没有留存（`prompt` 字段是事后才加的），
**所以无法判定是"提示词写了两个"还是"模型自己加了一个"** ——
这恰好说明了为什么提示词必须进证据链。

另外 `S03-001` 写 `["旅人","少女"]`，画面里有**三个人**（门口多一个）。

> **结论（可写进论文的局限）**：提示词能可靠约束**景别、运镜、风格**，
> **但不能可靠约束"画面里有几个人"**。后者是语义层的，属于 C2/C3 要处理的范围。

### ③ 桩路径的 `@名字` 标记漏进了提示词

桩的剧本用 `@名字` 标记角色，而它被原样拼进了提示词：

```
@少女 独自走在山坡上采花…（少女：…）
```

**解析标记不该漏进产物** —— 模型看到的是一个无意义的 `@`。已修（`_with_appearance` 里剥掉）。

### ④ 一个更值得注意的现象：**角色表与描述意图矛盾**

修完 `@` 之后看到：

```
角色 ['少女', '旅人']   但描述写的是"少女 独自 走在山坡上采花"
```

**"独自"与"两个人"是矛盾的**，而外观块按角色表注入了两个 ——
模型当然画两个。**这类矛盾是机器能查出来的**，
正是 C1「约束边 → 可执行断言」该管的事（目前还没有这条算子）。
