# `research/threshold-calibration/` —— 通过阈值的实测标定

**日期** 2026-10-17 · **版本** `0.4.0-alpha.41` · **样本** N = 10 · **脚本** `measure_threshold.py`

---

## 一句话结论

**阈值从 80 降到 65**，并且**未通过时改为交出"最好那一轮"而不是"最后一轮"**。

依据：**返工多数在让分数变差**（5/9），而"取最好一轮"让均值 +7 分、波动降 40%。

---

## 一、怎么测的

同一份素材（薰衣草传说）、同一套配置（编剧 DeepSeek / 剧评人 MiMo，跨族）、
同一上限（每集 3 轮），**跑 10 次**，逐轮记录：

- 权威总分（0~100）
- 裁定（PASS / REVISE / ESCALATE）
- 阻断级 / advisory 意见数
- 命中的场次数（完整性公式的分子）
- 每次调用的 token

原始数据 `raw.json`，汇总 `summary.json`。

---

## 二、结果

### 2.1 收敛率

| 阈值 | 收敛率 |
|---|---|
| **80（旧）** | **3/10 = 30%** |
| **65（新）** | **6/10 = 60%** |

轮数分布：`{1 轮: 1, 2 轮: 2, 3 轮: 7}`

### 2.2 ⚠️ 关键发现一：**返工多数在让质量变差**

| 结果 | 次数 |
|---|---|
| ↑ 变好 | **3** |
| ↓ **变差** | **5** |
| = 没动 | 1 |

逐次轨迹（首轮 → 末轮）：

```
# 1   46.2 -> 46.2   ( 0.0)   没动
# 2   80.2            (1 轮)  通过
# 3   55.6 -> 54.4   (-1.2)   变差
# 4   62.8 -> 57.6   (-5.1)   变差
# 5   70.8 -> 62.6   (-8.2)   变差
# 6   55.6 -> 80.2   (+24.6)  变好
# 7   67.9 -> 54.4   (-13.5)  变差  ← 降了 13.5 分
# 8   42.6 -> 62.6   (+20.0)  变好
# 9   63.8 -> 54.4   (-9.4)   变差
# 10  69.6 -> 81.6   (+12.0)  变好
```

**这意味着旧行为"取末轮"经常交出去的是几次里最差的一份。**

### 2.3 关键发现二：**取最好一轮是严格更优的策略**

| 指标 | 取末轮（旧） | **取最好一轮（新）** |
|---|---|---|
| 均值 | 63.4 | **70.3** |
| σ（波动） | 12.8 | **7.7**（降 40%） |
| p25 | 54.4 | 63.8 |
| p50 | 57.6 | **67.9** |
| p75 | 80.2 | 80.2 |
| 范围 | [46.2, 81.6] | **[62.6, 81.6]** |

**不增加任何成本** —— 只是从已有的几轮里挑分数最高的那一份。

### 2.4 阈值怎么选

按"取最好一轮"的分布：

| 阈值 | 通过率 |
|---|---|
| 55 / 60 | 100% |
| **65** | **60%** ← 选它 |
| 70 | 40% |
| 75 / 80 | 30% |

**为什么选 65**：让约六成的运行自动通过、四成升级人工。
那两个数字是**工作量分配**，不是质量指标 ——
想让更多集自动通过就往下调，想更严就往上调。

## 三、⚠️ 这个结果**不能**被读成什么

| 不能读成 | 为什么 |
|---|---|
| 「分数可信、可复现」 | ❌ **分数不可复现** —— 问题列表由 LLM 生成，每次不同 |
| 「65 是正确阈值」 | ❌ 它是一条**可调政策线**，换题材/模型/提示词都会变 |
| 「65 分 = 合格剧本」 | ❌ 完整性是**比例**，所以"2 场缺 1 场"= 76.9 分仍过 65 线 —— **短剧本对这个比例很敏感** |
| 「返工无效，该删掉」 | ❌ 它**3 次里有效**，且是发现真缺陷的唯一途径；问题在于**不该假设它单调改进** |

## 六、下一步该做什么

1. **样本量**：10 个样本估 p50，置信区间很宽。要更准需 30+ 次（约 ¥1 级成本，时间 1 小时）。
2. **换题材验证**：本标定只用一份素材。换一个故事重跑，看分布是否稳定 ——
   **如果题材间差异很大，"一个全局阈值"本身就是错的设计**，应按题材分组。
3. **short-script 敏感性**：完整性是比例，短剧本（2~3 场）对单个缺陷极其敏感。
   考虑改成"比例 + 最少缺陷绝对数"的组合，而不是纯比例。

# 附：条件对比实验（2026-10-17 追加）

上一轮标定只用了**一份素材、一种长度**。本轮追加两个条件，检验
"**一个全局阈值**"这个设计本身是否成立。

**脚本** `measure_conditions.py`，数据 `conditions.json` / `conditions-summary.json`。

## 三个条件

| 组 | 素材 | `max_scenes` | 变量 |
|---|---|---|---|
| **A 基准** | 薰衣草 | 8 | （上一轮的 10 次） |
| **B 短剧本** | 薰衣草（**同素材**） | **2** | 只改长度 |
| **C 换题材** | 都市悬疑（新） | 8 | 只改题材 |

## 结果（**0 分也计入** —— 见下方"分析错误"一节）

| 组 | n | 场景数 | 均值 | σ | p50 | 范围 | 通过 |
|---|---|---|---|---|---|---|---|
| A 基准 | 10 | ~5 | 70.3 | 7.7 | 67.9 | [62.6, 81.6] | 3/10 |
| **B 短剧本** | 5 | **2.0** | **52.6** | 11.4 | 44.4 | [44.4, 67.9] | 1/5 |
| **C 换题材** | 5 | 7.2 | **42.0** | **38.4** | 67.2 | **[0.0, 72.3]** | 3/5 |

## Q1 短剧本敏感性：**成立**，`B - A = -17.7 分`

**机制**：完整性是 `有缺陷的场次数 / 总场次` 这个**比例**。

| 剧本长度 | 缺 1 场时的不完整度 |
|---|---|
| 2 场 | **50%** |
| 5 场 | 20% |
| 8 场 | 12.5% |

实测最坏情况：**41.4 分**（2 场都有缺陷 → 完整性归零）。
而 B 组 5 次里有 **4 次**停在 41.4 —— **地板的**形状，不是连续的分布。

> **结论：同样的绝对缺陷量，短剧本被罚得重 3~4 倍。**
> "一个全局阈值"对短剧本**系统性不公平**。

## Q2 换题材：**均值差异不大，但分布形态完全不同**

C 组 5 次：`0.0 / 0.0 / 67.2 / 70.8 / 72.3` —— **两极分化**。

| 组 | 分布形状 |
|---|---|
| A 薰衣草 | **连续**（62.6 ~ 81.6，σ 7.7） |
| C 都市悬疑 | **两极**（作废或通过，σ 38.4） |

**这不是"题材分数低"，是两种不同的失败模式。**

## ⚠️ 新发现：`0.0` 是**判定作废**，不是"写得差"

C 组 **2/5（40%）** 的运行第 1 轮就 `ESCALATE`、分数 `0.0`。

**这两件事必须分开**（正是项目 §5.9 的判据）：

| | 含义 | 该怎么做 |
|---|---|---|
| 分数低 | 产物**不合格** | 返工 / 升级 |
| **判定作废（0 分）** | **判定不可信** | **升级人工，不给返工指令** |

**成因已缩小到一个分支**（2026-10-17 追查）：

`merge_reviews` 有 5 个返回 `ESCALATE` 的分支，而只有两个会给出 `total=0.0`：

| 分支 | 会不会给 0.0 |
|---|---|
| 自报分不自洽 | ❌ 给 `r.score.total` |
| 同族审核 | ❌ 给 `r.score.total` |
| 阻塞问题无返工指令 | ❌ 给 `total` |
| **没有任何审查意见** | ✅ **0.0** |
| **审查意见无维度评分** | ✅ **0.0** |

并且已核实：规则桩的 `story_editor` 只报 `MINOR`、`BLOCKER` 只出现在
审片（不在剧本闭环里）—— 所以"阻塞无指令"那条**不会触发**。

> **结论：那两次 `0.0` 是「评审侧没有产出可用意见」—— 即 LLM 调用失败，
> 不是"剧本写得差"。**

⚠️ **但试了 3 次复现，一次都没出现**（3 次全部通过）。所以它是**偶发**的，
成因只能定到"评审调用失败"这一层，**没有更细的证据**。

**已改进采集**：`measure_conditions.py` 现在会记录 `invalidatedReason` 字段 ——
下次跑就能直接看到具体是哪一条，不用再靠排除法。

## ⚠️ 我自己的一个分析错误（值得记）

第一版汇总脚本里写的是：

```python
"C": [r["bestScore"] for r in rows if r["bestScore"]]   # ← 0.0 是假值！
```

于是**两次 0 分的运行被悄悄排除**，C 组显示 n=3、均值 70.1、σ 2.6 ——
**看起来比 A 还好、还稳**。

修正后 n=5、均值 42.0、σ 38.4。**差别是天壤之别。**

> **这是"让失败样本消失"的标准错误** —— 而它恰好发生在
> **一个用来检验"我们是否在自欺"的实验里**。
> 教训：**汇总时必须显式检查"预期的 n"，而不是相信列表长度。**

## 对阈值的影响 —— 我的判断

**不建议再挪一次全局阈值。** 数据说明两件更根本的事：

| 问题 | 建议 |
|---|---|
| 短剧本被比例公式压到地板 | **改度量**，不是改阈值：加一个"绝对缺陷数"的下限保护，或对短剧本单独报告长度归一化分数 |
| 题材间失败模式不同（连续 vs 两极） | **先查清 40% 作废的成因** —— 审计链不稳定时，任何阈值都不成立 |
| 通过率 60%（A）/ 20%（B）/ 60%（C） | **如果按题材/长度分组，"一个全局阈值"就该被放弃** |

**下一步不是调数字，是查那两个 0 分。**

# 附二：**改度量**（2026-10-17，依据上一节的结论）

上一节的结论是"不建议再挪一次全局阈值，改度量"。本节记录改动。

## 改了什么

**完整性公式：从"比例"改成"按场次的绝对惩罚"。**

| | 旧 | 新 |
|---|---|---|
| 公式 | `100 × (1 - 缺陷场次/总场次)` | `max(0, 100 - 25 × 缺陷场次数)` |
| 缺陷 1 场 / 共 2 场 | 50 | **75** |
| 缺陷 1 场 / 共 8 场 | 87.5 | **75** |
| 缺陷 2 场 / 共 2 场 | **0** | **50** |
| 缺陷 4 场 / 共 5 场 | 0 | **0** |

**与剧本长度无关** —— "一场缺转折"在任何长度的剧本里都是同一件事。

## 实测效果（同一条件，2 场上限）

改度量前，短剧本组 5 次里 **4 次停在 41.4** ——
那是比例公式把完整性压成 0 之后的**地板分数**，
5 次里 4 次相同，说明它测的不是质量。

改度量后（3 次）:

| | 改度量前（5 次） | **改度量后（3 次）** |
|---|---|---|
| 分数 | 67.9 / **41.4 / 41.4 / 41.4 / 41.4** | **73.7 / 64.9 / 61.9** |
| 均值 | 46.7 | **66.8**（+20） |
| 相同值 | **4 次都是 41.4** | 无 |

**那 4 个相同的 41.4 就是地板** —— 5 次里有 4 次给出同一个数,
说明它测的不是质量。改完之后分数真的分开了（61.9 ~ 73.7）。

逐轮曲线也变得合理了：
```
73.7 那次：49.6 -> 58.9 -> 73.7（PASS，单调上升）
64.9 那次：61.9 -> 58.9 -> 64.9
61.9 那次：52.9 -> 61.9 -> 61.9
```
**不再有"改完反而掉到同一个地板"的假下降。**
主报告里"5 次改完变差"的现象，其中一部分很可能就是这么来的 ——
改得再好也撞 0，下一轮换个缺陷又涨回一点，看起来像"波动"而不是"地板"。

## ⚠️ 这个改动**不**主张"2 场剧本合格"

它只主张一件事：**同一个缺陷的代价应当可比**。

"一集只有 2 场"是不是问题，是**另一个独立判断** ——
不该藏在比例公式里当一个隐形惩罚。现在它会被如实看见：
2 场、2 场有缺陷 → 完整性 50，而不是被压成 0 让人看不出发生了什么。

## 走了一个弯路（值得记）

改完之后 **1205 项测试全过**，但跑真实一集时**连崩 3 次**：

```
NameError: name 'COMPLETENESS_PENALTY_PER_SCENE' is not defined
```

**漏了 import。为什么测试没抓到？**

| 测试 | 覆盖 |
|---|---|
| `crew_stubs_check` I 段（长度无关性） | **规则桩**的剧评人 |
| `crew_llm_check` G 段 | 只碰 `DramaturgeLlm().client`，**从不调用 `__call__`** |

**LLM 剧评人的执行路径一次都没被跑过。**

> **教训：一个类有单测，不等于它的 `__call__` 有单测。**
> "能构造"与"能工作"是两件事。

已补 `dramaturge_llm_check`（17 项，假客户端不吃 API），
其中 **A1「`__call__` 能跑通」** 就是当初缺的那一条。

## 新增的回归测试

| 位置 | 守什么 |
|---|---|
| `crew_stubs_check` I 段（5 项） | 规则桩：长度无关性、无缺陷满分、2 场全缺 = 50、4 缺陷归零 |
| `dramaturge_llm_check`（17 项） | **LLM 剧评人的整条执行路径** + 长度无关性 + 失败上报 + 输出规整 |

# 附三：加了传输层重试，然后**没能证明它有用**（2026-10-17）

## 改了什么

`LlmClient` 加了有限重试：**只重试 `retryable=True` 的失败**
（429 / 5xx / 网络异常），最多 2 次、指数退避。
4xx 这类语义失败**一次都不重试** —— 重试它只是把同一份账单再交一遍。

**动机**：C 组 5 次里 2 次**整轮判定作废、分数 0.0**。
查下去是评审调用失败，而 `review_artifact` 遇到任一审核者失败就中止整轮：

```python
if not out.ok:
    return (), f"审核者 {rid} 执行失败：{out.error}"
```

**一次网络抖动 = 一整轮作废 = 这一轮的 token 全白花。**

## A/B 结果 —— ⚠️ 关键在"重试 0 次"

同一条件（都市悬疑 / max_scenes=8）再跑 5 次：

| 项 | 改前 | 改后（带重试） |
|---|---|---|
| 整轮作废（0 分） | **2/5** | **0/5** |
| **重试触发次数** | — | **0 次** |
| 有效样本均值（排除 0 分） | 70.1（n=3） | **64.0**（n=5） |
| 通过 | 3/5 | 2/5 |
| σ | 38.4 | 10.2 |

**作废清零了，但一次重试都没触发。**

> **所以不能归因于重试。** 更可能的解释是**这次会话里服务更稳定**
> （或提供商恢复了）。
>
> **而且有效样本的均值反而降了 6.1 分** —— 这直接否掉了"改动带来系统性提升"
> 的说法。σ 从 38.4 降到 10.2 也**只是因为没有 0 分把方差撑开**，
> 不是分布变紧。

## 那重试还留着吗 —— 留

| 理由 | |
|---|---|
| **它是正确的防御** | 传输层失败重试是标准做法，代价可忽略（只在失败时触发） |
| **机制已被单测证明** | `crew_llm_check` H1~H6：可重试真重试、不可重试一次都不重试、抖动后成功对上层透明 |
| **这次没触发不等于以后不触发** | n=5 的"没发生"没有统计力量 |

**但汇报时必须写清楚：它的收益在本轮数据里是 0，不是"已验证有效"。**

## 这一节的真正结论

**那 40% 的作废是外部服务可用性问题，不是我们能靠重试消除的。**

要真正降下来，得做**我们控制范围内**的事：

| 可行 | 不可行 |
|---|---|
| 换更稳的审核方（换提供商 / 加兜底模型） | 让重试消除 40% 的失败率 |
| **把"评审失败"与"产物不合格"在报告里分开统计**（现在都表现成 0 分/未通过） | 靠调阈值掩盖 |
| 给审核方加"失败即重派"（换族重审）而不是整轮作废 | — |
